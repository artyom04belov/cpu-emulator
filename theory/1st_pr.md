# Первая практика. Основы устройства процессора (Конспет + инфа от гпт)

## 1. Бит, триггер и хранение информации

**Бит** — единица информации, принимающая значение 0 или 1.

**Триггер** — элемент цифровой схемы с двумя устойчивыми состояниями, способный хранить один бит. Обратная связь позволяет схеме сохранять установленное состояние после прекращения устанавливающего сигнала, пока сохраняется питание. Именно сохранение состояния даёт память.

Для дальнейшего изучения полезно различать защёлку, чувствительную к уровню разрешающего сигнала, и триггер, переключаемый по фронту тактового сигнала. Терминология в учебных курсах может различаться; в синхронных схемах важно понимать, в какой момент разрешено изменение состояния.

**Тактовый сигнал** координирует изменение состояния элементов схемы. Один период сигнала — один такт. Команда процессора не обязана выполняться за один такт.

## 2. Регистры и память

**Регистр** — небольшое хранилище фиксированного числа бит внутри процессора. Регистр шириной 32 бита хранит 32-разрядное слово. При беззнаковой интерпретации это число от 0 до 2³² − 1, то есть 4 294 967 295.

Аппаратный регистр обычно состоит из элементов хранения отдельных битов. Он принимает новое значение при разрешении записи и сохраняет старое, если запись не разрешена. Сам по себе регистр не складывает и не сравнивает числа.

**Регистры общего назначения (РОН)** хранят промежуточные данные, адреса и счётчики алгоритма. В нашем проекте это R0…R7.

**Специальные регистры** выполняют определённые функции:

| Обозначение | Название | Назначение |
|---|---|---|
| PC | Счётчик команд, Program Counter | Адрес команды для следующей выборки в рассматриваемой модели |
| IR | Регистр команды, Instruction Register | Выбранное машинное слово команды |
| MAR | Регистр адреса памяти | Адрес обращения к памяти |
| MDR | Регистр данных памяти | Передаваемое или полученное слово памяти |
| A, B | Регистры входных операндов | Временное хранение входов АЛУ |
| RES | Регистр результата | Временное хранение результата АЛУ |
| FLAGS | Регистр флагов | Признаки результата операции |

Названия A, B и RES условные. Конкретный процессор может иметь другую организацию; не все эти регистры доступны программисту и не все обязательно реализованы отдельными блоками.

**Память** — набор адресуемых ячеек. Адрес ячейки и её содержимое — разные вещи:

```text
Адрес:      20
Память[20]: 99
```

Число 20 указывает, где лежат данные, а 99 — сами данные. Если R0 = 20, то R0 содержит 20, а обращение [R0] читает память[20], то есть 99.

Для N адресуемых ячеек требуется как минимум ⌈log₂ N⌉ бит адреса. Объём памяти равен числу ячеек, умноженному на ширину ячейки. В нашем проекте 256 ячеек по 32 бита: 8192 бита, или 1024 байта. Адресация по словам: соседние адреса отличаются на 1 и обозначают соседние 32-битные слова. Это отличается от байтовой адресации.

## 3. Счётчик и счётчик команд

**Счётчик** хранит число и изменяет его по управляющему сигналу, например увеличивает на единицу. Аппаратно его можно построить из регистра и логики вычисления следующего значения.

**Счётчик команд PC хранит адрес, а не количество выполненных команд.**

```text
PC = 10  → выбрать команду по адресу 10
PC = 11  → выбрать следующую команду
JMP 30   → установить PC = 30
```

Для нашей модели обычное приращение PC равно 1, поскольку каждая команда занимает одно адресуемое слово. В других архитектурах оно зависит от единицы адресации и длины команды.

Счётчик цикла — другое понятие. Например, R2 может хранить число оставшихся элементов массива; команда SUB R2, #1 уменьшает его на единицу.

Память команд и счётчик сами по себе ещё не составляют полноценный процессор. Нужны декодирование, управление, обработка данных и запись результатов.

## 4. АЛУ и мультиплексирующая логика

**АЛУ — арифметико-логическое устройство.** Оно выполняет выбранную операцию над входными значениями: сложение, вычитание, сравнение, побитовые операции и другие предусмотренные действия. Конкретный набор зависит от реализации. Умножение может выполняться как частью учебного АЛУ, так и отдельным аппаратным блоком.

```text
Вход A = 7
Вход B = 5
Операция = ADD
Выход = 12
```

**Мультиплексор** выбирает один из нескольких входов и передаёт его значение на выход. Выбор задаётся управляющим сигналом. Мультиплексор не хранит данные и не выполняет арифметику.

Например, на второй вход АЛУ можно подать значение регистра, константу из команды или данные из памяти. Совокупность таких переключающих схем называют мультиплексирующей логикой.

**Регистр входного операнда** фиксирует значение перед обработкой. **Регистр результата** сохраняет выход АЛУ до последующей записи. Возможный тракт обработки:

```text
Регистры / память / константа
             ↓
     Выбор источников
             ↓
      Регистры A и B
             ↓
            АЛУ
             ↓
      Регистр RES
             ↓
  Запись в регистр или память
```

Это пример микроархитектуры, а не обязательное устройство каждого процессора. Устройство управления задаёт выбор источников, операцию АЛУ и разрешение записи.

**Комбинационная схема** определяет выход по текущим входам, без хранения состояния: примеры — мультиплексор и комбинационный сумматор. **Схема с памятью** имеет состояние, зависящее от предшествующих событий: примеры — регистр и счётчик. Такая разница помогает понять, зачем между вычислительными блоками ставят регистры.

## 5. Конечный автомат и управление

Конечный автомат — модель системы с конечным множеством состояний. Обозначим:

- A — множество возможных входных значений;
- B — множество возможных выходных значений;
- S — множество состояний;
- s₀ — начальное состояние;
- F — функцию перехода между состояниями;
- G — функцию формирования выходов.

Переход для обоих рассматриваемых типов: s_next = F(s, a).

| Тип автомата | Функция выхода | От чего зависит выход |
|---|---|---|
| Мура | b = G(s) | От текущего состояния |
| Мили | b = G(s, a) | От текущего состояния и текущего входа |

Фраза «у Мили есть прямая связь входа и выхода» — лишь неформальная подсказка. Точное отличие задаётся зависимостью функции выхода.

Управление учебным процессором можно описать автоматом: «выборка → декодирование → выполнение → выборка». Код операции и флаги влияют на действия и переходы. HALT переводит процессор в состояние остановки. Функции автомата управления определяют, какие блоки активны и какие регистры обновляются.

## 6. Архитектура системы команд и микроархитектура

**Архитектура системы команд (АСК, ISA)** описывает процессор с точки зрения машинной программы: команды, их кодирование и смысл, доступные регистры, типы данных, способы адресации и правила работы с памятью.

**Микроархитектура** описывает, как эти возможности реализованы: внутренние регистры, АЛУ, мультиплексоры, управляющие сигналы, стадии и конвейер. Одну АСК можно реализовать разными микроархитектурами.

Не следует смешивать процессор и всю вычислительную систему: основная память может физически находиться вне процессора.

## 7. Фон Нейман и Гарвард

**Архитектура фон Неймана:** команды и данные хранятся в общей памяти. Одно и то же слово интерпретируется как команда при выборке инструкции и как данные при обращении к данным. Это принцип хранимой программы в принятой учебной модели.

**Гарвардская архитектура:** память команд и память данных разделены, как и соответствующие пути доступа в классической модели. Их разрядности и объёмы могут различаться.

```text
Фон Нейман: процессор ↔ общая память команд и данных
Гарвард:    память команд ↔ процессор ↔ память данных
```

Современные реализации могут сочетать признаки этих подходов, например разделять кэши при общей основной памяти. Для нашей работы используется простая модель фон Неймана.

## 8. Команды, адресность и способы адресации

Команда содержит код операции (КОП) и, если нужно, поля операндов и режимов адресации. Литерал — значение, явно записанное в тексте программы; непосредственный операнд кодируется в самой команде. Операнды могут также находиться в регистрах или памяти. Некоторые команды, например HALT, не имеют явных операндов.

**Адресность** описывает количество явных адресных/операндных полей в рассматриваемом формате. Это не то же самое, что способ адресации.

```text
Трёхадресная: ADD R0, R1, R2 → R2 ← R0 + R1
Двухадресная: ADD R0, R1     → R0 ← R0 + R1
```

Здесь порядок полей трёхадресного примера соответствует исходной записи с пары. В других системах приёмник может стоять первым: порядок обязательно задаётся спецификацией.

В двухадресной арифметике один операнд обычно совмещает источник и приёмник. Переходы при этом могут иметь один операнд, а остановка — ни одного.

**Способ адресации** определяет, как получить операнд:

| Способ | Пример в нашем ассемблере | Значение |
|---|---|---|
| Непосредственная | #5 | Число 5 |
| Регистровая | R0 | Содержимое R0 |
| Прямая | [100] | Содержимое памяти по адресу 100 |
| Косвенная через регистр | [R0] | Содержимое памяти по адресу, находящемуся в R0 |

Метка — имя адреса, которое ассемблер заменяет числом. В нашей записи #array — адрес массива как константа, а array или [array] — данные по этому адресу. Для команды JMP метка означает адрес перехода.

## 9. Этапы выполнения и конвейер

Возможное учебное разбиение выполнения:

1. **Выборка (Fetch):** прочитать машинное слово по PC и сохранить в IR.
2. **Декодирование (Decode):** определить операцию и способы получения операндов.
3. **Подготовка операндов:** прочитать необходимые значения.
4. **Выполнение (Execute):** выполнить операцию или вычислить условие перехода.
5. **Запись результата (Writeback):** сохранить результат в предусмотренное место.

Доступ к памяти может выделяться отдельно. В распространённой пятистадийной конвейерной схеме используют Fetch, Decode/Register Read, Execute, Memory, Writeback. Это конкретный способ организации, а не обязательное разбиение любого процессора. Обновление PC также не обязано быть отдельной последней стадией.

В многоэтапном процессоре одна команда проходит несколько последовательных этапов. В **конвейере** разные команды одновременно находятся на разных стадиях. Разделение длинного пути вычислений регистрами может сократить необходимый период тактового сигнала, но простое выделение этапов в описании частоту не повышает. Конвейер прежде всего позволяет увеличить поток завершённых команд; отдельная команда не обязательно выполняется быстрее. Зависимости данных и переходы могут вызывать ожидание или отмену части работы.

### Пример ADD R0, R1

До команды R0 = 7, R1 = 5. Возможная последовательность микроопераций:

```text
MAR ← PC
MDR ← память[MAR]
IR  ← MDR
PC  ← PC + 1
Декодировать IR
A   ← R0
B   ← R1
RES ← A + B
R0  ← RES
Обновить флаги
```

После команды R0 = 12, R1 = 5. Это иллюстрация последовательности действий; одна строка не обязательно равна одному аппаратному такту. Наличие MAR, MDR, A, B и RES здесь — выбранный вариант внутреннего устройства.

## 10. Флаги, сравнение и переходы

Флаги сохраняют отдельные свойства результата. Их состав и правила обновления задаёт АСК.

В нашем эмуляторе:

- Z — нулевой результат арифметики или равенство при CMP;
- C — выход беззнакового арифметического результата за диапазон; при вычитании и CMP отмечает заём/отношение «меньше»;
- GT — первый операнд больше второго после CMP;
- LT — первый операнд меньше второго после CMP.

CMP сравнивает значения без изменения самих операндов. Арифметика обновляет Z/C и сбрасывает GT/LT. MOV и переходы сохраняют флаги. Поэтому переход по сравнению следует выполнять до команды, которая перезапишет нужные флаги.

```asm
CMP R0, R1
JB less       ; переход, если R0 < R1 без знака
JMP other     ; безусловный переход
```

Условный переход меняет PC при выполнении условия, иначе выполнение продолжается последовательно. Безусловный переход меняет PC всегда.

NOP не выполняет полезной операции, но процессор продолжает выборку. NOP не является остановкой. HALT останавливает выполнение; JMP на собственную метку создаёт бесконечный цикл. Последовательность NOP в конечной памяти сама по себе не обеспечивает бесконечного выполнения.

## 11. Беззнаковые числа и переполнение

Для n бит диапазон беззнакового целого: 0…2ⁿ − 1. При сохранении только младших n бит арифметика выполняется по модулю 2ⁿ.

```text
8 бит: 255 + 1 → 0, перенос
8 бит:   0 − 1 → 255, заём
```

В проекте используется 32-битная арифметика по модулю 2³². При свёртке произведения и суммы могут превысить диапазон даже при допустимых входах. Флаг C характеризует последнюю изменившую его операцию, а не всю программу. Если нужен точный результат без потерь, потребуется более широкое представление или ограничения на входные числа.

Беззнаковое сравнение отличается от знакового: например, 8 бит 11111111 означают 255 без знака или −1 в дополнительном коде. В нашем задании применяется беззнаковая интерпретация.

## 12. Ассемблер и машинный код

Ассемблер переводит текст программы в машинные слова. Парсер — часть ассемблера, которая разбирает синтаксис; кроме разбора нужны разрешение меток и кодирование.

Простой двухпроходный ассемблер:

1. Вычисляет размеры команд и данных, собирает адреса меток.
2. Заменяет метки адресами, проверяет операнды и формирует машинные слова.

Директива .word размещает данные в памяти; это не команда процессора. Комментарии и имена меток не выполняются процессором.

```asm
MOV R0, value
ADD R0, #1
HALT
value: .word 41
```

После выполнения R0 = 42. Ячейка value сохраняет 41, потому что результат записан в R0.

## 13. Пример системы команд с первой пары

В исходных записях рассматривалась **пузырьковая сортировка**: соседние элементы сравнивают и при неверном порядке меняют местами; проходы повторяют. Обычно её время в худшем случае O(n²). Это пример задачи с занятия, а не подтверждённая замена заданий нашего проекта.

Записанные мнемоники относятся к учебной системе команд. Их имена не являются универсальным стандартом. Ниже предлагается однозначная трактовка исходных записей; её следует сверить с преподавателем:

| Команда | Предлагаемый смысл |
|---|---|
| LTM address, literal | память[address] ← literal |
| LTR register, literal | register ← literal |
| MTR address_register, destination | destination ← память[address_register] |
| RTM source, address_register | память[address_register] ← source |
| ADD source1, source2, destination | destination ← source1 + source2 |
| SUB source1, source2, destination | destination ← source1 − source2 |
| JLESS source1, source2, target | Если source1 < source2, то PC ← target |
| JUMP target | PC ← target |
| NOP | Продолжить без полезной операции |

В строках MTR и RTM под address_register понимается содержимое регистра, используемое как адрес. В исходной записи у JLESS было «переход при лжи»: это противоречит естественной трактовке названия, поэтому выше предложен переход при истинности «меньше». Точная семантика исходной команды пока неизвестна. Записанное имя NOPE заменено обычным NOP; собственная мнемоника NOPE также возможна, если она определена в АСК.

ADD и SUB этого примера **трёхадресные**. Для нашего двухадресного процессора их нельзя перенести без изменения формата. Раздельные CMP и JB позволяют выразить сравнение и переход без трёхоперандной JLESS.

## 14. Что реализовано в нашем проекте

| Свойство | Текущая модель |
|---|---|
| Архитектура памяти | Фон Неймана: общая изменяемая память |
| Память | 256 слов по 32 бита |
| РОН | R0…R7, по 32 бита |
| Арифметические команды | Двухадресные, результат в первый операнд |
| Адресация | Непосредственная, регистровая, прямая, косвенная через регистр |
| Этапы интерфейса | Выборка → декодирование → выполнение |
| Задачи | Максимум массива и линейная свёртка двух массивов |
| Размеры массивов | По 6 входных элементов; у свёртки 11 выходных |

Команды представлены машинными словами в общей памяти. Формат слова: 8 бит КОП и два поля операндов по 12 бит. В поле операнда 2 бита задают режим, 10 бит — значение. Прямые адреса ограничены 0…255, номера регистров — 0…7, непосредственные константы — 0…1023. Большие значения uint32 размещаются через .word.

Текущая модель укрупнённая: подготовка операндов, работа АЛУ и запись результата объединены в этапе выполнения. A, B и RES не реализованы отдельными регистрами; мультиплексоры и их сигналы явно не моделируются. MAR/MDR отражают последнюю выборку команды, а не каждое обращение к данным. Конвейера нет. Поэтому окно показывает логические этапы, а не полную потактовую работу аппаратной схемы.

Разрядность, объём памяти, вид свёртки и правила переполнения приняты как рабочие решения. Для окончательной сдачи их необходимо сопоставить с требованиями преподавателя.

### Алгоритмы проекта

**Максимум:** принять первый элемент за текущий максимум, затем сравнить с ним остальные пять и обновлять при большем значении. Результат — значение максимума, без индекса. Порядок массива не меняется, сортировка не выполняется. Сложность O(n).

**Линейная свёртка:** обнулить C из 11 элементов и для i, j от 0 до 5 выполнять C[i+j] += A[i] × B[j]. Это соответствует C[k] = Σ A[i]B[k−i] по допустимым индексам. Сложность O(nm). В нашей реализации операции выполняются по модулю 2³².

Пример: A = [1, 2, 3, 4, 5, 6], B = [6, 5, 4, 3, 2, 1]. Тогда C = [6, 17, 32, 50, 70, 91, 70, 50, 32, 17, 6]. Например, C[1] = 1×5 + 2×6 = 17.

## 15. Как развивать учебную модель

Для более подробной демонстрации можно добавить отдельные A, B и RES, выделить подготовку операндов и запись результата в самостоятельные этапы, показывать выбор источников мультиплексорами и обновлять MAR/MDR при каждом доступе к памяти. Это предложения по развитию, а не уже реализованные возможности.

После освоения базовой модели полезно изучить задержки блоков и критический путь, конфликты доступа к общей памяти, зависимости данных в конвейере, стек и вызов подпрограмм. В первую очередь стоит научиться вручную прослеживать небольшую программу по состоянию PC, IR, регистров, флагов и памяти.
